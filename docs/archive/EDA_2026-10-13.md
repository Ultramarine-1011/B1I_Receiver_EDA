## 2. 新教师包的硬接口（已直接读取 `README.md` 和 SV）

- 路径实际有双层：`student_release/student_release/`。选**内层**为仿真工程目录，不要误用外层空壳。
- `input/scenario.if2` 为 **409,200,000 字节**（100 秒、6 星、40 dB-Hz、静态场景）。`input_contract.json`: Fs 16,368,000 Hz；IF 4,092,000 Hz；00/01/10/11 对应 -3/-1/+1/+3。
- **文件格式**每字节含 4 个 2-bit 样本，按 `[7:6]→[5:4]→[3:2]→[1:0]` 时间顺序；**进入 RTL 的总线** `stream_data[1:0]` 才是最早样本，`[31:30]` 是第 16 个，测试平台已自动反转每字节的 2-bit 顺序，学生 RTL **不得再次翻转**。
- `stream_valid && stream_ready` 每次交付 **16 个真实采样点**，`sample_index` 是这 16 个中最早采样的编号；下次增长 16。既有 `tracking_frontend.sv` 是**单样本输入**，需要在顶层做 16→1 拆包和 ready 背压；将每个拆出的样本依次配 `sample_index + 0..15`。
- `stream_last` 表示最后一个 16 点输入**传输**，不是最后一个已处理样本；清空内部流水、提交剩余记录后才发唯一 `type=6` 终止记录。输出为 256 bit `record_data`，`record_valid && record_ready` 表示被 TB 取走。
- 固定顶层：`rtl/student_receiver_core.sv`；可另加 RTL；`sim/`、`interface/`、`input/`、`scripts/`、`tools/` 为教师公共内容，不修改。参考 `submission/RECORD_FORMAT.md`。
- 教师脚本 `scripts/run_student_sim.ps1` 不是 Windows 原生仿真器：它调用 `wsl.exe -d Ubuntu`、`verilator --binary --timing`、Python。**不需要 VMware，但需要 WSL Ubuntu + Verilator + C++ 编译工具 + Python 依赖。** 本电脑实际安装状况尚未核实。
- 运行命令在内层 `student_release` 目录：`./scripts/run_student_sim.ps1 -DurationSeconds 0.01`（PowerShell）；逐步扩大至 0.1、1、20、100 s；完整场景不能拿短仿真替代。
- 自检 `tools/self_check.py` 预期至少 4 个捕获 PRN、非空锁定跟踪、至少一条 `type=2` 导航记录、有效 `type=4` 共同观测、唯一结束记录。其 PASS 是格式和存在性检查，**不代表真实捕获/解调/定位正确**。
- 有利发现：`tools/prompt_d1.py` 和 `route_a_position.py` 可以从 `type=1` 跟踪 Prompt（schema 2/3）做**软件 D1 诊断/恢复**，有利于验证同步方向。但本课程仍要求 RTL 解调，且默认 `self_check.py` 依然要求至少一条 `type=2`，不能用后处理功能冒充 RTL 完成。
